## 1. Level Design

### 1.1 Chapters 2-4 Have Identical Difficulty Curves

**Problem:** Chapters 2, 3, and 4 each have 15 levels that follow the exact same progression pattern:

```
Levels 1-2:   len:2, rem:1  (intro)
Levels 3-4:   len:3, rem:1  (easy)
Levels 5-6:   len:3, rem:2  (medium)
Levels 7-10:  len:4, rem:2  (medium-hard)
Levels 11-12: len:4, rem:3  (hard)
Levels 13-15: len:5, rem:3  (hardest)
```

The only difference is `newPc`. This makes the game feel like repeating the same 15-level gauntlet three times with a different piece skin.

**Solution:** Give each chapter its own difficulty fingerprint that reflects how its signature piece behaves musically.

**Chapter 2 (Neighbors) — "The Smooth Chapter"**
Neighbors have entry:0.5 / exit:0.5, which means they're the most flexible connector. The chapter should reflect this by introducing longer chains earlier but keeping removals low — the puzzle is about *choosing* which neighbor variant to use, not about managing many holes.

**Key design principles:**
- Each chapter has "breather" levels (long chains but few holes, or no forced newPc)
- `newPc:null` appears on ~30% of levels in each chapter, allowing pure mix puzzles
- Difficulty doesn't just ramp — it oscillates, with peaks followed by valleys
- Each chapter has a distinct "feel": Ch2=long chains, Ch3=high fill ratio, Ch4=aggressive mixing + a rem:4 boss

### 1.2 Every Non-Tutorial Level Forces newPc

**Problem:** In the current templates, every single level in Ch2-4 has `newPc:"Neighbor"` (or Approach/Enclosure). This means the puzzle generator *always* forces at least one instance of the chapter's signature piece into the solution. The player never gets a puzzle where they have to figure out the mix entirely on their own.

**Solution:** Already addressed in 1.1 above — approximately 30% of levels in each chapter have `newPc:null`. This creates variety:

- Early levels (1-5): `newPc` is set — ensures the player practices the new piece
- Mid levels (6-10): mix of `newPc` set and `null` — player starts to freestyle
- Late levels (11-15): more `null` — player must recognize all types by ear and position

The generator already handles `newPc:null` correctly (it just doesn't force any particular piece). No code change needed beyond the template updates.

### 1.4 Chord Progressions Are Random, Not Idiomatic

**Problem:** The current `pickRandomChords()` function just picks random chords:
- Body chords: random min7 or dom7
- Last body chord: always dom7
- Target: random maj7

This means you can get progressions like `Fm7 → E7 → Abmaj7` which has no tonal relationship. In bebop, ii-V-I in a key is the bread and butter. The game is supposed to teach jazz — the chords should *sound* like jazz.

**Solution:** Replace `pickRandomChords` with a key-aware ii-V-I generator.

```javascript
// ==================================================================
// CHORD POOL — key-center based ii-V-I progressions
// ==================================================================
const KEY_PROGRESSIONS = {
    // key: { ii, V, I }
    'C':  { ii: 'Dm7',  V: 'G7',   I: 'Cmaj7' },
    'F':  { ii: 'Gm7',  V: 'C7',   I: 'Fmaj7' },
    'Bb': { ii: 'Cm7',  V: 'F7',   I: 'Bbmaj7' },
    'Eb': { ii: 'Fm7',  V: 'Bb7',  I: 'Ebmaj7' },
    'Ab': { ii: 'Bbm7', V: 'Eb7',  I: 'Abmaj7' },
    'G':  { ii: 'Am7',  V: 'D7',   I: 'Gmaj7' },
    'D':  { ii: 'Em7',  V: 'A7',   I: 'Dmaj7' },
};

// Additional ii-V pairs that resolve to different keys (for longer progressions)
// These create "secondary dominants" — e.g., ii-V of IV before resolving to I
const SECONDARY_IIVS = {
    'C':  [{ ii: 'Gm7',  V: 'C7'  }],  // ii-V of F (IV of C)
    'F':  [{ ii: 'Cm7',  V: 'F7'  }],  // ii-V of Bb (IV of F)
    'Bb': [{ ii: 'Fm7',  V: 'Bb7' }],
    'Eb': [{ ii: 'Bbm7', V: 'Eb7' }],
    'G':  [{ ii: 'Dm7',  V: 'G7'  }],
    'D':  [{ ii: 'Am7',  V: 'D7'  }],
};

function pickRandomChords(count) {
    const keys = Object.keys(KEY_PROGRESSIONS);
    const key = keys[Math.floor(Math.random() * keys.length)];
    const prog = KEY_PROGRESSIONS[key];

    let chords;
    switch (count) {
        case 2:
            // ii → V, resolving to I (target)
            chords = [prog.ii, prog.V];
            break;
        case 3:
            // Three options, weighted randomly:
            // a) ii → V → V (repeated dominant for tension) — rare
            // b) ii → ii → V (lingering on ii) — most common
            // c) secondary ii-V → V (modulating approach) — medium
            if (Math.random() < 0.5) {
                chords = [prog.ii, prog.ii, prog.V];
            } else {
                // Pick a secondary ii-V from a related key
                const secKeys = Object.keys(SECONDARY_IIVS);
                const secKey = secKeys[Math.floor(Math.random() * secKeys.length)];
                const sec = SECONDARY_IIVS[secKey][0];
                chords = [sec.ii, sec.V, prog.V];
            }
            break;
        case 4:
            // Classic: secondary ii-V → primary ii → V
            // or: ii → V → ii → V (double ii-V — very common in standards)
            if (Math.random() < 0.6) {
                chords = [prog.ii, prog.V, prog.ii, prog.V];
            } else {
                const secKeys = Object.keys(SECONDARY_IIVS);
                const secKey = secKeys[Math.floor(Math.random() * secKeys.length)];
                const sec = SECONDARY_IIVS[secKey][0];
                chords = [sec.ii, sec.V, prog.ii, prog.V];
            }
            break;
        case 5:
        default:
            // Extended: secondary ii-V → primary ii-V → V
            // or: ii → V → ii → V → ii (turnaround feel)
            if (Math.random() < 0.5) {
                const secKeys = Object.keys(SECONDARY_IIVS);
                const secKey = secKeys[Math.floor(Math.random() * secKeys.length)];
                const sec = SECONDARY_IIVS[secKey][0];
                chords = [sec.ii, sec.V, prog.ii, prog.V, prog.ii];
            } else {
                chords = [prog.ii, prog.V, prog.ii, prog.V, prog.ii];
            }
            // For counts > 5 (composer mode), repeat ii-V pairs
            while (chords.length < count) {
                chords.unshift(Math.random() < 0.5 ? prog.ii : prog.V);
            }
            chords = chords.slice(0, count);
            break;
    }

    return { chords, targetChord: prog.I };
}
```

**Why this matters:**
- Every progression now resolves to I in a real key
- The player hears actual bebop harmony: `Dm7 → G7 → Cmaj7` instead of `Fm7 → E7 → Abmaj7`
- Longer progressions use secondary dominants, a real jazz concept
- The target chord is *always* the I chord of the key — this is how bebop lines actually resolve
- Educational value: players internalize ii-V-I patterns by ear

**Tutorial levels don't change** — they already use `Dm7 → G7 → Cmaj7` (ii-V-I in C).

### 1.5 Star Unlock Thresholds Are Inconsistent

**Problem:**
| Chapter | Needs | From Max | Percentage |
|---------|-------|----------|------------|
| Ch2     | 12★   | 24★ (8×3) | 50% |
| Ch3     | 20★   | 45★ (15×3) | 44% |
| Ch4     | 20★   | 45★ (15×3) | 44% |
| Ch5     | 20★   | 45★ (15×3) | 44% |
| Ch6     | 20★   | 45★ (15×3) | 44% |

Ch2 requires proportionally more stars from Ch1 than any other unlock. This makes early progression feel gated.

**Solution:** Normalize to ~40% across all chapters, with a slight upward trend as chapters get harder (players improve and earn more stars naturally).

```javascript
const CHAPTERS = [
    { id:1, name:"Arpeggios",   icon:"Arpeggio",  unlockStars:0,  color:"gold",   reward:null },
    { id:2, name:"Neighbors",   icon:"Neighbor",   unlockStars:10, color:"purple", reward:"Neighbor" },   // was 12, now 10 (42% of 24)

    { id:4, name:"Enclosures",  icon:"Enclosure",  unlockStars:20, color:"green",  reward:"Enclosure" },  // stays 20 (44% of 45)
    { id:5, name:"All Mixed",   icon:"🎷",         unlockStars:22, color:"red",    reward:null },          // was 20, now 22 (49% — harder unlock for endgame)

```

**Rationale:**
- Ch2 unlock drops from 12→10: early players shouldn't feel blocked. Getting 10 stars from 8 levels = averaging 1.25★ per level, very achievable.
- Ch3 drops slightly to 18: keeps the flow going.
- Ch4 stays at 20: by now the player is competent.
- Ch5 rises to 22: all four piece types is a real step up, should require demonstrated skill.
- Ch6 rises to 25: Jam Session is the prestige chapter — you should earn your spot.

function renderConnectionDots() {
    // Remove existing dots and lines
    document.querySelectorAll('.connection-dot, .connection-line').forEach(el => el.remove());

    const cellGap = window.innerWidth <= 480 ? 8 : 12;

    for (let col = 0; col <= numCols; col++) {
        if (!gridState[col]) continue;
        const { piece, position } = gridState[col];
        if (piece.name === 'Target') continue;

        const column = document.querySelector(`.grid-column[data-col="${col}"]`);
        if (!column) continue;
        const firstCell = column.querySelector('.grid-cell');
        if (!firstCell) continue;
        const cellH = firstCell.offsetHeight;

        const entryY = piece.entryY !== undefined ? piece.entryY : 0.5;
        const exitY = piece.exitY !== undefined ? piece.exitY : 0.5;

        // Entry dot (left side)
        const entryDot = document.createElement('div');
        entryDot.className = 'connection-dot entry';
        const entryTopPx = position * (cellH + cellGap) + entryY * cellH;
        entryDot.style.top = (entryTopPx - 4) + 'px';
        column.appendChild(entryDot);

        // Exit dot (right side)
        const exitDot = document.createElement('div');
        exitDot.className = 'connection-dot exit';
        const exitTopPx = position * (cellH + cellGap) + exitY * cellH;
        exitDot.style.top = (exitTopPx - 4) + 'px';
        column.appendChild(exitDot);

        // Check connection with right neighbor
        const rightCol = col + 1;
        if (rightCol <= numCols && gridState[rightCol]) {
            const rightPiece = gridState[rightCol].piece;
            const rightPos = gridState[rightCol].position;
            const rightEntryY = rightPiece.entryY !== undefined ? rightPiece.entryY : 0.5;

            const myExitAbsolute = position + exitY;
            const rightEntryAbsolute = rightPos + rightEntryY;

            if (Math.abs(myExitAbsolute - rightEntryAbsolute) < 0.01) {
                // Connected! Mark dots green
                exitDot.classList.add('connected');

                const rightColumn = document.querySelector(`.grid-column[data-col="${rightCol}"]`);
                if (rightColumn) {
                    const rightEntryDots = rightColumn.querySelectorAll('.connection-dot.entry');
                    // The entry dot for the right column will be rendered in the next iteration;
                    // we'll mark it connected when we get there.
                    // For now, mark this exit dot.
                }
            }
        }

        // Check connection with left neighbor (mark entry dot if connected)
        const leftCol = col - 1;
        if (leftCol >= 0 && gridState[leftCol]) {
            const leftPiece = gridState[leftCol].piece;
            const leftPos = gridState[leftCol].position;
            const leftExitY = leftPiece.exitY !== undefined ? leftPiece.exitY : 0.5;

            const leftExitAbsolute = leftPos + leftExitY;
            const myEntryAbsolute = position + entryY;

            if (Math.abs(leftExitAbsolute - myEntryAbsolute) < 0.01) {
                entryDot.classList.add('connected');
            }
        }
    }
}

### 3.1 "Sing It Back" — Encouraging Vocalization

#### Layer 2: Scat Syllable Rhythm Display (Chapters 1-2 only)

On early levels, after the first playback of each level, briefly show the *rhythm* of the melody as scat syllables. This helps players who don't know what to sing.

**How it works:**

The melody has 4 notes per piece column + 1 target = groups of 4 eighth notes. With swing, the rhythm alternates long-short. Scat syllables make this tangible:

```
DOO-bah-DOO-bah   DOO-bah-DOO-bah   DOO
```

Where uppercase = on-beat (long), lowercase = off-beat (short).

**JS:**

```javascript
let singBackScatShown = false; // reset per level in startLevel()

    // Only on chapters 1-2, only on first playback of this level
    if (!currentLevelData || currentLevelData.chapter > 2) return;
    if (singBackScatShown) return;
    singBackScatShown = true;

    // Build scat string from the melody structure
    const noteGroups = [];
    for (let col = 0; col < numCols; col++) {
        // Each column has 4 eighth notes
        noteGroups.push('DOO-bah-DOO-bah');
    }
    noteGroups.push('DOO'); // target note

    const scatText = noteGroups.join('   ');

    const el = document.getElementById('sing-back-text');
    if (el) {
        el.textContent = scatText;
        el.style.fontFamily = "'JetBrains Mono', monospace";
        el.style.fontSize = '11px';
        el.style.letterSpacing = '0.04em';
    }
}
```

### 3.5 "Hear the Shape" — Teaching Pieces Through Sound, Not Text

**Problem:** When a player unlocks a new piece (Neighbor, Approach, Enclosure), the reward screen shows a thumbnail and a paragraph of text: *"Decorates the target note by stepping to an adjacent tone and returning. **Solution:** Replace the text description with **auto-playing the piece's 4 notes** through the Rhodes piano while **animating the melodic contour** on the piece thumbnail. The player simultaneously sees the shape and hears the shape. That *is* the lesson.

**JS — the auto-play + animation sequence:**

```javascript
let rewardPieceName = null;
let rewardNotes = [];

function playRewardPieceNotes() {
    if (rewardNotes.length === 0) return;

    getAudioCtx();
    getMasterGain(); // ensure Rhodes chain is connected

    const eighth = getEighth();
    const swingRatio = soundParams.swing;
    const swingLong = eighth * 2 * swingRatio;
    const swingShort = eighth * 2 * (1 - swingRatio);

    let t = audioCtx.currentTime + 0.1;
    const dots = document.querySelectorAll('#reward-note-dots .reward-note-dot');

    rewardNotes.forEach((midi, i) => {
        const isOnBeat = (i % 2 === 0);
        const dur = isOnBeat ? swingLong : swingShort;

        // Schedule note
        playNote(midiToFreq(midi), t, dur * 0.9);

        // Schedule dot animation (synchronized to audio clock)
        const delayMs = (t - audioCtx.currentTime) * 1000;
        setTimeout(() => {
            // Deactivate previous dot
            if (i > 0 && dots[i - 1]) {
                dots[i - 1].classList.remove('active');
                dots[i - 1].classList.add('fading');
            }
            // Activate current dot
            if (dots[i]) {
                dots[i].classList.add('active');
            }
        }, Math.max(0, delayMs));

        t += dur;
    });

    // Fade last dot after final note
    const totalMs = (t - audioCtx.currentTime) * 1000 + 200;
    setTimeout(() => {
        dots.forEach(d => {
            d.classList.remove('active');
            d.classList.add('fading');
        });
    }, totalMs);
}

function replayRewardPiece() {
    // Reset dots
    document.querySelectorAll('#reward-note-dots .reward-note-dot').forEach(d => {
        d.classList.remove('active', 'fading');
    });
    // Regenerate notes (random intervals give slight variation each replay)
    rewardNotes = generateRewardNotes(rewardPieceName);
    playRewardPieceNotes();
}
```

#### Contextual tooltips for flip and duplicate introduction

**Flip tooltip (level 3):**

Already covered by section 3.4 Trigger A (wrong placement with right type, wrong direction). Since ch1_03 requires Descending but tray gives Ascending, the player will either:
- Try placing it → wrong direction → tooltip fires: *"Right piece, wrong direction! Drag it here to flip it ⇌"*
- Wait 15 seconds → proactive tooltip fires (Trigger B)

No changes needed — section 3.4 handles this perfectly. The tutorial text ("This piece needs to go the other way!") primes the player, and the tooltip shows them where.

**Duplicate tooltip (level 6) — NEW:**

Similar pattern to the flip tooltip but for duplication. Two triggers:

**Trigger A (reactive):** Player places their only piece correctly in one slot, but the tray is now empty and another column is still empty. After 8 seconds with an empty tray and unsolved columns:

```javascript
let dupeTooltipShown = false;
let dupeProactiveTimeout = null;

function shouldShowDupeTooltip() {
    return !dupeTooltipShown && !localStorage.getItem('bebopDupeTooltipDone');
}

function markDupeTooltipDone() {
    dupeTooltipShown = true;
    localStorage.setItem('bebopDupeTooltipDone', '1');
}

function scheduleDupeProactiveHint() {
    if (!shouldShowDupeTooltip()) return;
    if (dupeProactiveTimeout) clearTimeout(dupeProactiveTimeout);

    dupeProactiveTimeout = setTimeout(() => {
        // Check: tray empty, unsolved columns remain, craft table visible
        if (!shouldShowDupeTooltip()) return;
        const unsolved = currentLevelData.removeCols.filter(c => !gridState[c]);
        if (trayAvailable.length === 0 && unsolved.length > 0 && craftOpen) {
            showDupeTooltip();
        }
    }, 8000);
}
```

**Trigger B (after wrong attempt to drag from empty tray):** If the player taps/clicks an empty tray area, show the tooltip immediately.

**The tooltip itself:**

```javascript
function showDupeTooltip() {
    const dupeBtn = document.getElementById('craft-dupe-btn');
    // Point at the craft drop zone if nothing is in craft, or the dupe button if a piece is loaded
    const target = craftStack.length > 0 ? dupeBtn : document.getElementById('craft-drop-zone');
    if (!target) return;

    let text;
    if (craftStack.length > 0) {
        text = 'Press Duplicate to make a copy!';
    } else {
        text = 'Need more pieces? Drag one here, then duplicate it!';
    }

    showTooltipAt(target, text, 'arrow-up');
    markDupeTooltipDone();
    setTimeout(() => removeTutorialTooltip(), 6000);
}
```

**Call `scheduleDupeProactiveHint()`** at two points:
1. At the end of `startLevel()` (for levels with `craft:'full'` and `rem >= 2`)
2. In `checkAnswer()` after a correct placement (the tray might now be empty)

```javascript
// In checkAnswer(), after a correct placement:
if (nameMatch && labelMatch && posMatch) {
    // ... existing correct-answer handling ...

    // Schedule dupe hint if tray just became empty
    if (trayAvailable.length === 0 && shouldShowDupeTooltip()) {
        scheduleDupeProactiveHint();
    }
}
```

#### Why this pacing works

**Cognitive load per level:**

| Level | New concepts introduced | Total concepts active |
|-------|------------------------|----------------------|
| 1 | Listen, drag, snap, place | 4 (core) |
| 2 | Position awareness | 4 + 1 |
| 3 | Flip | 5 + 1 |
| 4 | — | 6 (practice) |
| 5 | — | 6 (practice) |
| 6 | Duplicate | 6 + 1 |
| 7 | — | 7 (practice) |
| 8 | — | 7 (mastery) |

No level introduces more than 1 new concept. Every new concept gets 2+ practice levels before the next one arrives. By level 8, the player has used every mechanic multiple times.

**Alternative pacing considered:**

Introducing duplicate at level 5 instead of 6 would give 4 combined-practice levels (5–8) instead of 3 (6–8). But the user's instinct to give 3 flip-practice levels (3, 4, 5) before adding duplicate is better — flip is the harder concept because it requires understanding *direction*, while duplicate is just "make a copy." More time on the harder skill.
